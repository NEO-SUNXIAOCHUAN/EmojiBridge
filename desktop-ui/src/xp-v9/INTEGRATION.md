# V9 动作与耗时模型

这是设计预览与可移植的动作代码，不是 Windows 正式程序修复。当前版本以新录屏为参考：真实成功时立即停止环境经验球，定格最终等级并清空条；原速完整升级音响一次，再让瓶子从右侧进入吸收。

`motion.cjs` 导出 `createMotion({elapsedSeconds})`，输入真实任务的单调时钟耗时。返回 `level`、`timeline`、`sample(timeSinceSuccess, width, barX, barY, scale)`、`pose(...)` 等。没有固定的 8 或 12 级分支；成功等级为 `max(8, floor(elapsedSeconds))`。不足 8 秒按 8 级收尾只影响装饰表现，结果立即可用，不为凑 8 秒阻塞任务。运行中仍是每秒一级。小数部分不额外凑一级。999 以后继续正常整数，没有取模回零；像素数字按位数居中，正常支持三位数。

相对 V8 只调整两个动作：入场和倾斜由 0.52 秒放慢到 0.80 秒，退场由 0.38 秒放慢到 0.65 秒。升级音、吸收节奏、条与数字、回正动作和像素资产保持不变。

成功相对时刻：1.36 秒瓶子入场，2.16 秒已倾斜并开始吸收；吸收 1.65–2.25 秒（随等级适度变化但有上限），接着 0.28 秒回正、0.65 秒退场，最后 0.36 秒零级空条待机。成功音完整 1.31 秒，瓶子在旋律完成后入场。正式任务完成不依赖这些动画结束。

等级与条来自同一减少中的经验量。普通等级（8–32）按游戏逆向逻辑：整数等级的条为空，开始吸收时退到上一级的满条，条向左消退，再退一级。结束严格是 0 级、空条。更高等级把条的消退分为 12 组，数字仍按真实剩余经验倒数；这避免把 137 次满空闪动挤进两秒。`barCycles` 明确标识分组，不伪称每组必减一级。粒子最多 48 颗，运行时只计算当前活动颗粒，不按总耗时累积对象。

瓶口对准条，粒子路径终点使用旋转后真实瓶口。轻微像素响应仅发生在粒子入瓶时；装满后沿用原 16×16 附魔瓶及局部紫蓝流光，回正后向右上退场。未增加瓶子声音。

`ending.js` 是现有像素渲染器的接入片段，依赖其 `setState`、`drawXP`、`digitText`、`imgs.empty/full`、`spriteCache`、`canvas/ctx`、`w/h/barX/barY/scale`。另需 `root.motion`、`root.bottles` 和 `root.paintBottleGlint`。它不能独立启动。`render.cjs` 引用保留的 V4 内联绘制快照，仅用于生成审看视频，不是正式架构要求。

视频是试听示例：主视频包含 0.6 秒待机和 8 秒运行；三位数短片省略了 137 秒等待，直接展示真正耗时 137 秒之后的收尾。视频固定时长不能替代正式任务状态。`output/*-timeline.json` 记录真实媒体时刻、音轨来源与增益。音频源未变速、未变调；默认 XP 音量 35%，完成声相对 0.54。内嵌视频使用原相对增益，交给预览音量控件调节。

`test-motion.cjs` 检查 17 组秒数，包括小数、不足 8、27、99、100、137、999、1000 与 3600 秒；检查剩余量单调、起止状态、条与数字关联、运动边界连续、颗粒与时长上限。不包含真实 Windows、浏览器或听感测试。

取消、失败、新任务、隐藏和恢复必须通过独立任务身份处理，旧动作/旧音频不得清掉新任务。资源释放和实际任务状态必须在动画之外保证。程序卡死原因尚未由这份动画原型定位；需要拿正式工程复现并检查后台任务、并发上限、超时取消及强退后的恢复。
