# 动画状态参考

此模块只协调表现状态，当前未接入正式 Windows 程序。它不运行抠图、不保存作品、不结束后台任务，也不能证明原软件卡死已经修好。

`createLifecycle({ now, onEffect, closingDuration })` 接收以秒为单位的单调时钟。运行时 `sample()` 的等级为实际经过秒数的整数部分，条为小数部分；不靠定时器累加等级。成功时等级为 `max(8, floor(elapsedSeconds))`，不足 8 秒只是收尾采用 8 级，真实结果立即可用，不强制等待满 8 秒。数字不取模、不限制成 8 或 12，999 之后继续显示 1000，渲染器须保留足够宽度。

- `start()` 返回本轮 token；真实任务成功后调用 `complete(token)`。该操作立即标记结果可用，再发一次成功音效事件并进入收尾。
- `cancel(token)` / `error(token)` 接受真实取消、失败事件，直接回待机，不播成功音。它们本身不会取消后台计算，任务所有者仍负责其真正的取消与回收。
- 收尾结束调用 `ended(token)`；跳过收尾调用 `skip(token)`。每次 `sample()` 也检查绝对截止时间，漏掉结束事件后，下次采样仍会复位。宿主可在可见帧、恢复可见性、操作事件或轻量看门狗中采样；本模块不自动启动定时器，也不能挽救整个 UI 线程被阻塞。
- `registerCleanup(token, fn)` 登记帧回调、音频、监听器等表现资源的停止函数，最多同时 32 项。开始新一轮、成功切收尾、取消、失败、复位、销毁都会清理适用资源；陈旧或超额登记立即执行清理。不要将任务、原文件或结果文件删除操作登记在此处。
- `reset()` 幂等；`dispose()` 幂等并终止该实例的表现资源。卸载后丢弃旧 token 的 UI 回调，后台任务及其结果由外部任务管理器继续管理。

`onEffect` 的事件：`presentation-start`、`running-stop`、`result-ready`、`success-sound`、`closing-start`、`presentation-stop`。每个事件带 token；异步解码、音频播放及素材加载完成后仍须核对 token。清理函数或表现事件抛错不会阻断结果标记，但宿主应收集错误诊断。程序自身读写失败、内存耗尽和强退恢复属于另一层，仍要在正式工程定位验证。

收尾时间可与动作模块保持一致：传入 `closingDuration: level => createMotion({ elapsedSeconds: level }).timeline.end`。默认 5.8 秒，配置值最多 30 秒，避免坏参数将表现状态长期挂住。隐藏后恢复只采样当前状态，不补发积压经验球、等级音或逐秒任务。

`node lifecycle.test.cjs` 覆盖任意秒数、三位数及四位数、短任务立即交付、成功音只一次、取消/失败、旧回调、缺失结束事件、1,000 次混合循环、表现异常和资源上限。它是纯状态测试，不是 Windows 防死机验收。
